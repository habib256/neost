Help & shortcuts
  • Mouse: click the middle button (usually the wheel), or press Ctrl+Alt+G, to capture or release it (GEM cursor). While it is captured, Esc belongs to the browser and releases it (a browser rule the page cannot change); otherwise Esc and Del are sent to the ST.
  • Keyboard: routed to the IKBD; letters follow your keyboard layout and the TOS language (AZERTY under a French TOS), other keys are positional (US layout). Keyboard joystick: arrows + right Alt (right Option on a Mac) = fire, on the port picked in the Joystick box (port 1 by default).
  • USB pads: detected automatically — first pad on port 1, second on port 0. The dead zone slider only affects analog sticks, not the D-pad.
  • Reset: a cold reset (power-cycle) — ST-RAM is wiped and TOS boots from scratch, which is also what "Mount A: + Reset" and Shift+drop do.
  • Keys the browser would take (F1–F12, arrows, Space, Page Up/Down, Ctrl/Alt+letter) go to the ST while the screen has the focus or the mouse is captured: click the screen first.
  • Game floppies: "Mount A: + Reset" switches to a real TOS when one is available (EmuTOS boots system floppies only) — TOS 2.06 on STE/Mega STE, TOS 1.0x on ST. This build bundles EmuTOS alone, which is free software; original Atari TOS ROMs are not ours to ship. Most commercial games therefore need your own TOS image: drop it on the screen (.img / .rom / .tos / .bin). It is loaded in this page only — never uploaded — joins the ROM list and boots cold; a TOS 1.04 or older turns an STE back into an ST, as on the desktop. The bundled demos boot fine on EmuTOS.
  • Demos: pick one and press Run demo. The page reloads with the machine, the RAM and the TOS that demo was checked with — EmuTOS at 50 Hz, since these productions were written for PAL screens — and boots straight into it. The demos that do not run under EmuTOS are not offered here.
  • Save states: ⤓ Save state downloads the whole machine (CPU, RAM, every chip) as a .state file; drop it on the screen to come back to that instant. It restores only on the same machine model, RAM size and exact ROM image. The floppies in A: and B: are inside it, writes included: after a reload, a floppy you had dropped comes back from the state (a .stx or .ipf image must be dropped again first). A hard disk folder (C:, D:) is not inside it.
  • Touch screens: Touch mouse (on by default on phones and tablets) turns the screen into a touchpad — drag to move, tap to click, tap with two fingers for a right click; hold L or R to keep a button down (dragging in GEM). Touch joystick: slide your finger on the pad (eight directions), FIRE and SPACE on the right, plugged into the port picked in the Joystick box. ST keyboard: Atari ST keys sent as they are; Shift, Ctrl and Alt stay down until the next key (tap again to release). Letters are labelled for the TOS language (AZERTY under a French TOS, QWERTZ under a German one). In full screen, the buttons at the top right open the keyboard and the joystick, and ✕ leaves. On a touch device, the Boot floppy…, Insert floppy… and Open state / TOS… buttons replace dropping a file.
  • Screenshot: saves what the screen shows — the cropped picture when Auto zoom is on — as a PNG, low resolution pixels doubled to keep the screen's shape.
  • Drag and drop: drop a .st / .msa / .dim / .stx / .ipf image onto the screen to insert it in A: without a reset — that is how you swap to "disk 2" mid-game. Hold Shift while dropping to mount it and reboot.
  • Your floppies live in this page only: what the ST writes to them (saved games…) is lost when the page is closed or reloaded. ⤓ Download A: saves the floppy in A: with its writes (for .stx/.ipf, which are never rewritten, it saves the .wd1772 file that holds the writes — Hatari reads it too).
  • Hard disk (GEMDOS): Folder as C:… and Folder as D:… copy a folder of your computer into the page and show it to the ST as a hard disk — tools on C:, your work on D:, for example. Empty D: gives a blank D:. Start at boot names a program the desktop launches at each boot (C:\DEVPAC\DEVPAC.PRG). Each change reboots the ST. Nothing is uploaded, and the files live in this page only: ⤓ Download C:/D: (.zip) saves them, with what the ST wrote, before you close or reload it; Load .zip… brings such an archive back next time. A teacher can also give a link that sets everything up: index.html?machine=st&mem=1m&mono=1&hd=course.zip&boot=C:\DEVPAC\DEVPAC.PRG loads course.zip (served next to the page, with C/ and D/ folders) and starts the program. Pages that embed NeoST can do the same from JavaScript (README, "GEMDOS drives for pages embedding NeoST").
  • Machine & RAM: fixed when the machine is built → changing them reloads the page (URL parameters ?machine= and ?mem=, shareable). You are asked first when a floppy of yours is in use.
  • Sound: browsers require a user gesture — the first click or key press anywhere on the page unlocks audio (YM2149 + STE DMA + drive noises).
